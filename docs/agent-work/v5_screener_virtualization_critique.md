# v5 스크리너 행 가상화 (S-PERF1) 도입에 따른 성능/안정성 비평 및 가이드라인

> **문서 상태**: 선제적 비평 단계 (Pre-emptive Critique)  
> **대상 범위**: 스크리너 가상화(`S-PERF1`, `Slice C`) 도입 계획에 따른 렌더 성능 및 데이터 무결성 검증  
> **검토 목적**: 대량 데이터(1,066종목) 가상화 렌더링 시 Next.js SSR 환경 및 동적 확장 상태에서 발생할 기술적 지뢰밭 식별  

---

## 1. 가상화 도입 시 3대 기술 리스크 (Virtualization Pitfalls)

```
[Critical Risk] 1. 동적 행 높이 확장 오동작 (Dynamic Height Collapse)
    └── 인라인 상세 패널 확장 시 행 높이가 가변적으로 변하나, 가상화 엔진이 캐시를 갱신하지 못해 겹침 발생
[High Risk] 2. Hydration Mismatch & SSR SEO 훼손
    └── 서버 사이드에서 전체 테이블을 그리지 않아 Hydration 시점의 불일치 및 SEO 봇 수집 범위 축소
[Medium Risk] 3. 빠른 스크롤 시 상태 휘발 & 비동기 재로딩 (State Loop)
    └── 행이 뷰포트 밖으로 벗어나 언마운트될 때, 로컬 확장 상태 및 개별 데이터 페칭 캐시 유실
```

### [P0] 리스크 1: 동적 행 높이 확장 오동작 및 레이아웃 누수 (Dynamic Height Collapse)
- **현상**: 스크리너는 `StockDetailPanel` (~2,017 lines)을 테이블 내 인라인으로 확장(`inline expand`)하는 구조입니다. 확장 전 행 높이는 약 48px이지만, 확장 후에는 차트, 금융 데이터 표 등이 추가되어 500px 이상으로 동적으로 늘어납니다.
- **위험**: `react-window`와 같은 가상화 라이브러리는 렌더링 최적화를 위해 각 행의 위치 정보를 절대 좌표(`position: absolute`)와 고정 높이 캐시로 관리합니다. 행이 열릴 때 가상화 캐시가 명시적으로 리사이징(`recomputeRowHeights` 또는 `cache.clear()`)되지 않으면 행들이 서로 겹쳐서 UI가 완전히 붕괴되는 치명적인 오작동이 발생합니다.

### [P1] 리스크 2: SSR 환경에서의 Hydration Mismatch 및 SEO 훼손
- **현상**: Next.js App Router는 서버 사이드에서 정적 마크업을 생성하여 전달합니다. 하지만 가상화 라이브러리는 클라이언트 브라우저의 실제 컨테이너 높이(`window.innerHeight` 등)와 스크롤 위치를 알아야만 렌더링 범위를 결정할 수 있습니다.
- **위험**: 서버에서는 가상화 없이 테이블 전체를 그리고 클라이언트에서는 뷰포트 영역만 그리려고 시도할 때 Hydration Mismatch 오류가 강제 발생하여 React 트리 렌더링이 깨집니다. 또한, 서버 사이드 렌더링 마크업에 스크롤 밖의 1000여 개 종목 데이터가 누락되어 검색 엔진 수집 품질이 급락합니다.

### [P2] 리스크 3: 스크롤 속도에 따른 상태 휘발 및 비동기 재로딩 루프
- **현상**: 가상화 엔진은 스크롤에 의해 화면 밖으로 벗어난 행 DOM을 강제로 언마운트(destroy)하고, 새로운 행을 마운트하여 재사용합니다.
- **위험**: 사용자가 30번째 행을 확장해서 차트를 관찰하다가 잠시 위로 스크롤한 뒤 다시 내려오면, 해당 행이 언마운트되었다가 재마운트되면서 확장 상태 및 차트 API 비동기 캐시가 유실되어 다시 로딩 스피너가 돌며 껌벅이는 조악한 피로감을 주게 됩니다.

## 2. 권장 아키텍처 및 구현 설계안 (Architectural Guide)

성공적인 가상화 구현을 위해 아래 3가지 하이 레벨 가이드라인을 반드시 수립해야 합니다.

1. **하이브리드 SSR & 가상화 탈출 가드 (SSR Fallback)**:
   - 서버 사이드 렌더링 및 클라이언트 최초 hydration 시점에는 가상화를 비활성화하고, 첫 페이지 분량(50개 로우)만 표준 HTML 테이블 구조로 일반 렌더링합니다.
   - 컴포넌트 마운트 완료(`mounted === true`) 및 브라우저 환경이 확인된 직후에만 가상화 그리드로 부드럽게 점진적 향상(Progressive Enhancement)을 실행하여 Hydration mismatch를 차단합니다.
2. **동적 높이 리사이징 캐시 동기화**:
   - `react-window` 대신 동적 리사이징 지원이 유연한 `react-virtuoso` 컴포넌트 채택을 강력 권장합니다.
   - 만약 `react-window`를 고수한다면, 상세 패널 토글 함수 실행 시 즉각적으로 가상화 인스턴스의 `resetAfterIndex(index)` API를 버스트 호출하여 행 높이 변화를 가상화 엔진 좌표계에 정밀 동기화해야 합니다.
3. **확장 및 데이터 상태 격리 (State Liftoff)**:
   - 각 행의 확장 상태(`isExpanded`) 및 페칭 완료된 종목 금융 데이터는 개별 로우 컴포넌트의 로컬 상태(Local state)로 두지 말고, 스크리너 최상단 콘텍스트(`ScreenerContext` 또는 `zustand`)로 끌어올려(Liftoff) 가상화로 인한 DOM 파괴 후 복구 시에도 껌벅임 없이 이전 상태가 유지되도록 보장합니다.

## 3. Slice C 최종 롤아웃 게이트 (Rollout Gate Requirements)

- [ ] **성능 벤치마크**: 1,066개 종목 전체 로드 상태에서 스크롤 시 초당 프레임 수(FPS)가 모바일 웹킷 50FPS, 데스크톱 크롬 60FPS 이상을 지속할 것.
- [ ] **Hydration 에러 무결성**: 가상화 탭 진입 시 브라우저 콘솔에 React Hydration Mismatch Warning이 단 1건도 기록되지 않을 것.
- [ ] **상태 메모리 보존 검증**: 행 확장 후 스크롤을 끝까지 내렸다가 다시 원래 행으로 돌아왔을 때, 확장된 디테일 패널 및 차트가 재로딩 스피너 없이 즉시 렌더링될 것.
